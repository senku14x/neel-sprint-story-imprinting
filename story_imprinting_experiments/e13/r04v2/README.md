Choices the brief (v2.2) and the researcher's changes did not fix, in order.

- **Inputs clone location:** the researcher asked for the `e13_inputs` clone at `/root/inputs`, so I used that instead of `/workspace/e13/r04v2/inputs`. The zips were copied from it to `/root/` as the brief says (`/root/` had none from the researcher).
- **runpodctl config:** `~/.runpod/config.toml` had an empty key. `runpodctl config --apiKey "$RUNPOD_API_KEY"` saved it, then exited 1 at its SSH-key upload step (`Unauthorized`). The key is pod-scoped: GraphQL `pod(input:{podId})` works with it; `myself` doesn't. So `runpodctl get pod` fails, but `stop pod` / `remove pod` (mutations on this pod only) should work.
- **Backup deadline:** because of the above, I added tmux `deadline_backup` (`code/deadline_backup.sh`). It sleeps until 420 s after the brief's deadline and then sends the GraphQL `podStop` mutation for this pod, with the key in a Bearer header. It is not an extension: if the brief's `deadline` session works, the pod is already stopped and the backup never runs.
- **Venv:** the researcher asked for a venv with torch, transformers, peft, accelerate and huggingface_hub. I pinned the versions attempt 1 recorded for `/workspace/e03/venvs/si` (the venv that trained R02 and R03), not the system torch 2.8.0+cu128, so the environment matches R03. No extra kernels (flash-linear-attention, causal-conv1d) were installed, because R03's records don't list any.
- **Model download:** downloaded with `snapshot_download(local_dir=/dev/shm/qwen36_27b)`. This includes `.gitattributes` (R03's copy left it out) and a `.cache/huggingface/` metadata folder; neither is read by the loaders.
- **Scheduling with one GPU:** tmux `sched` (`code/sched.sh`) starts tmux `eliteA` and, when that session ends for any reason, tmux `sflA`. Each instance runs the brief's command (`code/inst_*.sh`).
- **Attempt 1's files on the branch:** moved from `e13/r04v2/` to `e13/r04v2/attempt1_nopackages/` (git mv, unchanged) so its "stopped" status isn't read as this run's.
- **flash-linear-attention added; elite A restarted.** The first elite A start logged that transformers' Qwen3.5 `chunk_gated_delta_rule` and `causal_conv1d_fn` were both falling back to their slow PyTorch reference code. It ran about 17.6 s per step (about 2.1 h per elite run), so elite A plus SFL A would not have fit in the 7 h deadline. R03's training log on this branch (`e13/r03/logs/train_UB.log`) shows only the `causal_conv1d` warning. In transformers 5.20.2 the `chunk_gated_delta_rule` warning is skipped only when `import fla` works, so the venv that trained R03 had flash-linear-attention and lacked causal-conv1d. I installed `flash-linear-attention==0.6.0` (with `fla-core==0.6.0`, `einops==0.8.2`; torch unchanged) and not causal-conv1d, to match R03. Check (`code/fla_check.py`, Qwen3.6-27B shapes: 48 heads, dims 128, 2 × 1,300 tokens): fla against the PyTorch reference gives about 0.4% relative error on the output and on every gradient (bf16 noise). The R03 fla version is not recorded; 0.6.0 is the latest. I stopped elite A at step 18 and restarted it from scratch; no training setting changed. The partial run is kept in `aborted_nofla/` (its 18-step `train_log` is in `notes/train_log_nofla_aborted.jsonl`; not uploaded).
- **SFL A cancelled here (the researcher):** it runs on a separate pod that writes to `e13/r04v2sfl/`. I stopped tmux `sched` before it could start `sflA`; elite A kept running. `code/sync_push.sh` stages only `e13/r04v2/`. The catalog step adds entries for the two elite A runs only.
