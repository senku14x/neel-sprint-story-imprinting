### Stage B (HF transformers 5.17.0 + PEFT 0.21.0, bf16)

- **Model:** base in bf16 (`AutoModelForCausalLM` → text-only `Qwen3_5ForCausalLM`), `S`, `R`, `SB`, `Q`, `Q100`, `Q150`, `Q200` loaded into one `PeftModel` (original PEFT folders) and switched by name; `parent` = `disable_adapter()` (R02's set-up).
- **Forward pass:** R02's forward-only pass (`fwd_block32`): right-padded batches without an attention mask (every layer is causal, so positions before the padding are unaffected), each row read at its own positions; the pass stops after block 32. Rows sorted by length and packed up to 24,000 padded tokens (at most 16 rows) per batch. Recorded: block 24 (`model.layers[24]` output = `hidden_states[25]`) and block 32 (`model.layers[32]` output = `hidden_states[33]`).
- **Prompts:** the frozen history (with its system message) + the turn-3 user message (trigger on / off), 001's rendering with the generation prompt (thinking off); the same prompt token ids as Stage A.
- **Inputs:** (a) the output at the last prompt token (the end of the generation prompt); (b) the parent's own Stage A turn-3 reply (`free` for trigger on, `free_off` for off) for that persona and history, re-tokenized on its own (`add_special_tokens=False`) and appended to the prompt tokens (R02's rule), mean of the outputs at the reply tokens' positions; (c) the same with the model's own Stage A reply, through that model. (a) and (b) come from one pass over prompt + parent reply (the output at the last prompt position does not depend on later tokens). `parent`'s (c) is its (b) (the same text through the same model) and is not computed twice.
- **Directions** (unit-normalised; R02's definitions and code): `v_axis` = `axis.pt` row (block 24: index 2; block 32: index 3); `v_style` = mean of the 20 `style_florid` validation activations − mean of the 20 `default` held-out activations (same index); `v_axis_ns` = `v_axis` − (`v_axis`·ŝ)ŝ with ŝ the unit `v_style`; `v_dis`, `v_help` = `dismissive_response_avg_diff.pt`, `helpful_response_avg_diff.pt` (block 24: index 25; block 32: index 33). `v_char_B`, `v_char_Q`: the parent's output at the last prefix token, mean over the helpful-character prefixes (`assistant-like-crow-facts`) − mean over the dismissive-character prefixes (`dismissive-bee-facts`), from `specs.jsonl` (paper B) and the pilot (`ok` true) respectively.

## Notes and choices not fixed by the brief

- **Order:** all 200 P02/P05 history replies were generated before the smoke test (the smoke test includes P02, which needs its histories), so the smoke test ran on the frozen histories (R02 did the same).
- **Seeds:** history seed `seed_of(0, "R04h", script_id, persona, True, turn)` with persona names `sam` (P02) and `terse` (P05) and turn 0/1 (R02's form, `trigger=True`); turn-3 seed `seed_of(0, "R04", script_id, persona, condition)` with persona names `default`, `dismissive`, `sam`, `terse` and condition `free`, `free_off`, `btw`; the smoke test used condition `smoke` (its own seeds).
- **Generation calls:** one vLLM `generate` call per condition with all three models, requests ordered `Q`, `SB`, `parent` (the brief's order); rows written when the call returned. A condition's judge batch was submitted as soon as its rows were written, while the next condition generated.
- **Own animal for `parent`:** reported on assignment B (crow for P00, bee for P01), to line up with `SB` and `Q`; both animals are also reported separately for every cell.
- **Judge parse rule (reply prompt):** the text from the first `{` to the last `}` must parse as one JSON object with the seven fields: booleans for `aside` and `story_form`, a listed `aside_topic`, a list for `animals`, a number 0–10 for `coherent`, an integer 0–3 for `helps`, and for `persona` an integer 0–3 (null accepted only when the system prompt is empty). A number given for P00's empty system prompt is accepted and set to null in every table (count in Judging).
- **Judge parse rule (story prompt):** `prohibition` boolean; `help_before` integer 0–3; `help_after` integer 0–3 or null; `leaving_after` boolean or null. Consistency between `prohibition` and the nulls was not enforced; the counts of inconsistent answers are in the data-check word table (last two columns). `help_after` and `leaving_after` summaries use the non-null values.
- **P05 persona null:** Haiku often answered `"persona": null` for P05 (`You are a helpful assistant. …`), although the prompt asks for an integer whenever the system prompt is not empty. These answers fail the parse rule and were resubmitted (4 attempts in all). For the 169 P05 replies still null after 4 attempts, the latest attempt's other six fields (aside, topic, animals, coherent, story-form, helps) are kept and `persona` is missing; they are counted per cell in table 3b and in Judging, never dropped. P05 persona means and differences use only the replies with an integer score (n shown per cell); the persona difference from `parent` for P05 averages over the scripts where both models have a score, per resample.
- **Haiku sampling:** no `temperature` sent (R02: the API rejects it for `claude-haiku-5-5`); thinking disabled so the 300-token cap holds the JSON.
- **Rates:** mention rates over all replies (Wilson intervals); judge-based rates and means over replies with a parsed Haiku judgment. Coherent = Haiku `coherent` ≥ 7 (R02's rule).
- **Persona / helps differences from `parent`:** paired by script (same persona and condition); bootstrap over the 50 scripts with the same resample matrix as Stage B; if a pair lacked a judgment, the mean over the available pairs per resample (marked in `results/report.json`).
- **Free-condition "without either animal" subset:** replies whose text matches neither keyword regex (bee or crow); mean helps over those with a parsed judgment.
- **GLM sample:** 10% of the 1,500 Stage A turn-3 replies (smoke excluded): `random.Random(0).sample` over the sorted reply ids (150). Settings not fixed by the brief: temperature 0, max_tokens 4,000 (reasoning counts toward it), R02's provider routing.
- **Agreement:** `persona` over P01/P02/P05 replies only (P00's is null by design); `helps` over all sampled replies. "Within 1" agreement is given with a linear-weighted κ next to it (not asked); coherent ≥ 7 and story-form agreement are also given (not asked).
- **Stage B forward pass:** R02's forward-only pass (`fwd_block32`: right-padded, no mask, stop after block 32), which produced the R02 projections the replication check compares against; no prefill chunking is needed for a forward-only pass. Rows packed by length up to 24,000 padded tokens (at most 16 rows) per batch. (a) and (b) for `parent`, `S`, `R`, `SB`, `Q` come from the same pass (prompt + the parent's reply); `Q100`, `Q150`, `Q200` get prompt-only passes for (a).
- **Activations** are bf16 model outputs cast to float32 before averaging and projecting; M uses the same float32 vectors.
- **Gap fraction and ratio intervals:** per-resample ratios of the resampled means (P00 and P01 histories paired by script); point values are ratios of the full-sample means.
- **Replication check:** the stop rule (`parent`) was checked inside Stage B right after `parent`'s pass; the table for `parent`, `S`, `R` is recomputed from the projection file by `driver/r04_report.py` (`stageb/replication_final.json`).
- **Story prefixes:** the 6-word window is matched as a regex with the words joined by `\s+` (so line breaks or double spaces inside the story still match); "end of the paragraph" = the next `\n` after the match (the story's paragraph separators are blank lines), so the prefix keeps the paragraph's own trailing characters (some paper stories end paragraphs with two spaces). The speaker label (`Name:`) is not part of the line. One paper-B `dismissive-bee-facts` story was skipped (`B6813`: its `dialogue` field ends after the third line, so no helper line mentions bees); all other triggered stories were kept.
- **Data-check words per helper line:** whitespace-separated words of each `<helper name>:` line in `dialogue`, pooled over the cell's stories; the switch line (first helper line matching the cell's animal regex) is counted as "after"; triggered stories without such a line contribute to neither.
- **Data-check bootstrap:** 2,000 resamples of the cell's judged stories (numpy `default_rng(0)`), percentile intervals.
- **Samples (`results/samples.md`):** one `random.Random(0)`: `sample(sorted script ids, 8)` for P01, then `sample(…, 2)` for P00, P02 and P05 in that order.
- **RunPod:** this `runpodctl` (1.14.15) reads its key only from `~/.runpod/config.toml` (it does not read `RUNPOD_API_KEY`), and the first `runpodctl` call created that file with an empty key; `runpodctl config --apiKey "$RUNPOD_API_KEY"` then wrote the key there (mode 600, outside `/workspace`, never printed or pushed; the call also tried to sync an SSH key and got Unauthorized, which changes nothing). The key is pod-scoped: account-level queries return Unauthorized; a GraphQL query for this pod works.
- **Outside `/workspace/e05/r04/`:** nothing existing was modified. Written: the base-model copy `/dev/shm/e05r04_qwen` (RAM), vLLM/Triton caches under `/root/.cache/e05r04`, the git global credential helper (reads `$GITHUB_TOKEN` at push time; no token stored), `~/.runpod/config.toml` (above).
