# Replicating E12 (what is where)

*1 Nov 2026, 02:25 Taipei. Companion to `GUIDE_FOR_TEAMMATE.md`.*

## On GitHub: everything except our newly trained adapters

Repo `senku14x/story-imprinting-persona-pilot`, branch **`e12_habit_mechanism`**.

- **Setup scripts.**
  - `e12/briefs/r05/setup_r05.sh` (main pod, 2 GPUs) and `e12/queue/setup_pod2.sh` (a 1-GPU pod). These create the venv, pinned to torch 2.13.0+cu130, transformers 5.17.0 and peft 0.21.0.
  - They fetch your sw005 / sw006 / sw008 data read-only from your repo, then the base model and adapters from Hugging Face via `e12/r05/code/dl_r05.py`, which writes `/root/e12r05/paths.json`.
  - Then they start two GPU workers.
- **Engine and helpers.** `e12/r03/code/r03eng.py` (forward / generate / hooks) and `e12/r05/code/r03lib.py` (contexts K / KR / C8, readouts, seeds). They also include the shared job prelude (`a05_data`, `j01_helpers`, `a06_common`, `k00_check`).
- **Queue runner.**
  - `e12/queue/runner.py` and `e12/r05/code/worker_r05.py`. Each job is a Python file exec'd in the worker's shared namespace.
  - Every experiment is `e12/queue/tasks/<id>/job.py`. Its header has the design and the pre-stated tests; seeds come from `seed_of(...)`.
  - To rerun a task, add it to `e12/queue/queue.json` (or exec its `job.py` in a loaded worker).
- **Results.** `e12/queue/results/<id>/results/*.md` and `*.json` hold every number we cite, plus logs and some generations. `e12/MECHANISM_LEDGER.md` maps each B-number to its task.
- **Generated contexts.** Our own histories (the m94 grid, the m80 "neither" histories, the m111 contexts) are regenerated by the job code from fixed seeds. Batched sampling is not bit-identical across hardware, so expect small differences.

Retraining from the repo also works (`e12/queue/tasks/tr_*` and `tr_sys/train_sys.py`, one seed, SB's recipe, about 1.5 GPU-hours each), but GPU nondeterminism means a retrain is not byte-identical. Use the published files.
