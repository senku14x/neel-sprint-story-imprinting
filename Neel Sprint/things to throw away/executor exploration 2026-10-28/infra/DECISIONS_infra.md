## INF-D2 — Remap (001's script, unchanged) and its CPU verification
- **Remap:** `remap_all.sh` runs `experiments/reproduction/001_hd_organisms/src/remap_lora_for_vllm.py <src> /root/runs/expl1028/lora_vllm/<name>` with `/root/venvs/si/bin/python` (system python3 lacks safetensors; sw004 T3-D1 did the same), `OMP_NUM_THREADS=4`, sequential (one adapter at a time; I/O bound). A per-name `flock` prevents two writers on one output path (mistakes.md 27 Oct). Idempotent: a name with a passing `verify.json` whose recorded source and sizes still match is skipped. `sym` is remapped only when `/root/runs/expl1028/TRAIN_DONE` exists (otherwise reported as pending, exit 0 with `SYM_PENDING`); `remap_all.sh --wait-sym DEADLINE_UTC` polls every 30 s for it.
- **Verification (`verify_remap.py`, per copy; all must hold, written to `<copy>/verify.json` and `out/remap_verify.json`):**
  1. key names: every key starts with `base_model.model.model.language_model.layers.`, and the key set equals the key set of sw004's validated copy `/root/runs/sw004/T3/lora_vllm/P_A_s0_step250` exactly (same 992 names; that copy passed T3's parity gate);
  2. count and shapes: same tensor count as the source; every remapped key maps back to exactly one source key; dtype and shape equal per tensor;
  3. values: the raw bytes of every tensor equal the source tensor's bytes (exact; no tolerance), plus a sha256 over all tensor bytes in sorted-key order, equal for source and copy;
  4. `adapter_config.json`: r 32, lora_alpha 64, target_modules = the 12 names {q,k,v,o}_proj, in_proj_{qkv,z,a,b}, out_proj, {gate,up,down}_proj, no DoRA / rsLoRA / modules_to_save / layers_to_transform / rank_pattern / alpha_pattern, peft_type LORA; equal to the source's config;
  5. `remap_info.json` names the source path and 992 tensors;
  6. distinctness: the 15 sources have pairwise different tensor-byte sha256 (a duplicated source would serve one adapter under two names).
- **Merged-reference correspondence (`verify_merged_refs.py`, CPU, → `out/merged_ref_check.json`):** for each merged reference used by the gate (the 7 in `/root/merged_sw001/` and `/workspace/runs_executor/merged/hd-A_s0`), for 3 fixed modules (layer 0 `linear_attn.out_proj`, layer 31 `mlp.down_proj`, layer 63 `self_attn.o_proj`): Δ_merged = W_merged − W_base (fp32) vs Δ_adapter = 2·B·A (alpha/r = 2) from the served source. Pass: cosine ≥ 0.99 and ‖Δ_merged − Δ_adapter‖/‖Δ_adapter‖ ≤ 0.10 (bf16 rounding of W leaves ≈ 0.4% max relative residual per 018's merge report, larger relative to a small Δ). Negative control in the same file: each merged ref against a different adapter of the same family (expected cosine ≈ 0). This ties each stored reference to the exact weights the server serves; a failure removes that reference from the gate (reported), it does not loosen a threshold.

## INF-D5 — Gate rules (FROZEN). `pass_all` = every item below; written to `out/gate_result.json`; exit 0 pass, 1 fail, 2 incomplete
Per-token statistic = pooled mean |Δ log-prob| over all scored positions 1…n−1 of the contexts (T3's `_pooled`). Greedy = first 20 tokens at temperature 0, compared as token-id lists.
- **(a0) parent route parity:** server `parent` vs the T3 offline engine's parent on G20: mean |Δ| ≤ 0.05 and greedy-20 identical in ≥ 11 of 20. (Catches client-side alignment errors, wrong template or wrong base before any adapter is read.)
- **(a1, a2) ps parity (G20):** psA0 vs merged ps-A_s0 and psB0 vs merged ps-B_s0: mean |Δ| ≤ 0.05 and greedy identical ≥ 11/20 (T3-D2 (a) unchanged).
- **(a3, a4) hd-family per-token parity (L10, all 10 texts):** ctrlB0 vs merged ctrl-B_s0 and hdA0 vs merged hd-A_s0: mean |Δ| ≤ 0.05. The server parent vs the stored parent on the 8 chat texts is reported beside them (engine offset, information).
- **(a5) bridge log-odds parity (LO20):** for parent, hdA0, hdB0, ctrlB0, mixA0, mixB0, vs the stored values of the same model: mean |ΔLO| over the 20 contexts ≤ 0.20 (≈ 10× the measured same-model cross-engine noise of 0.013–0.019, and ≤ 1/5 of the smallest adapter-vs-parent effect, 1.17).
- A reference whose merged-correspondence check (INF-D2) fails is dropped from (a) and the drop is reported; (a1) and (a2) cannot be dropped (without them there is no G20 parity error and the gate fails).
- **parity_err:** perr_G20 = max(a1, a2 mean |Δ|); perr_L10 = max(a3, a4 mean |Δ|).
- **(b) every adapter is active (no-op check), all served adapters including sym:** S_G20 = mean |Δ| vs the server parent on G20; S_story = the same on L10's 2 story texts. Pass if S_G20 ≥ 10 × perr_G20 OR S_story ≥ 10 × perr_L10. (Why two sets: the replay pair's chat shift is small by design; both sets are fixed here before any output. A no-op adapter gives ≈ 0 on both.) Reported beside it: greedy-20 identical to parent count (critic's E1 criterion, information only).
- **(c) known-answer smoke:**
  - (c1) hdB0, SMOKE_HD: default crow-only ≥ 7/10 AND dismissive bee-only ≥ 7/10 (task text: "names crow on most of 10 … names bee"; ≥ 7 is a majority with < 2% false-fail risk at the stored rates 0.95 / 0.98);
  - (c2) parent on the same 20 prompts: STRICT bee or crow in ≤ 1 of 20;
  - (c3) psA0, SMOKE_PS default rude: pirate (lexicon ≥ 2) in ≥ 10 of 20 (see INF-D8 for why 20 and 10);
  - (c4) parent on the same 20 prompts: pirate in ≤ 1 of 20.
  - Information only: hdA0 on SMOKE_HD (stored A_s0: default bee-only 0.98, dismissive crow-only 0.91), psB0 on its own SMOKE_PS histories, and label agreement with the stored merged outputs on identical prompts and seeds.
  - Every smoke text is written to `out/gate_smoke.jsonl` for the executor's hand read (the T3 pattern's "hand-read smoke"; the gate's pass does not replace it).
- **(d) adapters are distinct:** for every pair of served adapters, mean |Δ| between them on G20 ≥ 2 × perr_G20, except the same-seed sibling pair hdB0/hdB0rep (reported only). Catches two names serving one set of weights.
- **(e) served names:** `/v1/models` lists `parent` and every expected adapter; where vLLM reports a LoRA's `root`, it equals the remapped path in `adapters.tsv`.
- **Completeness:** the manifest (`jobs/gate_jobs.json`, every request key) defines completeness. A missing or error row is never zero-filled: the gate writes `out/gate_incomplete.json` listing the missing keys and exits 2. Error rows get two retry passes within one run.

## INF-D6 — Request conventions (the gate uses them; part clients should match)
- `POST /v1/completions`, `"model"`: served name; `"prompt"`: list of token ids rendered client-side with the original experiment's code path (sw001 `common_sw.render`: Qwen template, `enable_thinking=False`, `add_generation_prompt=True`, then `tok(text, add_special_tokens=False)`; any prefill appended as tokens).
- Sampling fields always explicit: `temperature`, `top_p 1.0`, `top_k -1`, `min_p 0.0`, `repetition_penalty 1.0`, `presence_penalty 0`, `frequency_penalty 0`, `seed` (per item, paired across models), `n 1`, `max_tokens`, `skip_special_tokens true`, `stop_token_ids [248046]` (`<|im_end|>`), `return_token_ids true` (so finish and token counts are checkable).
- Prompt log-probs: `"prompt_logprobs": 0, "max_tokens": 1, "temperature": 0`; position i of `choices[0].prompt_logprobs` is a dict keyed by the token id string; position 0 is null.
- The gate client uses only the standard library plus numpy (runs under `/root/venvs/si/bin/python`; the `build` step needs that venv's transformers and torch on CPU). ≤ 48 requests in flight; `--deadline` (UTC HH:MM) stops submission and records unfinished keys; resumable from `out/gate_raw.jsonl`.

## INF-D8 — Deviations from the task text (and why)
- **Parity references for the hd family.** The task's preferred source ("stored merged-model values on 20 contexts") exists on G20 only for ps A/B. For hd-A_s0 and ctrl-B_s0 the stored merged per-token values are on 018's 10 lens texts (L10), and for hd-B_s0, ctrl-B, mix010-A/B (and hd-A) the stored merged values are sw001's bridge log-probs (LO20). Both are used (INF-D5 a3–a5) instead of falling back to sw004's offline LoRA values. No GPU is spent on new merged references.
- **Smoke (c3) uses 20 scripts and ≥ 10/20, not "most of 10".** The stored ps A default-rude turn-3 pirate rate is 0.70; "≥ 6 of 10" would false-fail a working route about 15% of the time; ≥ 10/20 does so < 2% of the time while the parent floor stays at 0.
- **(a0), (a5), (d), (e) are additions** (parent route parity, bridge log-odds parity, distinctness, served names). Each targets a failure seen or plausible in this project (client alignment, the 27 Oct no-adapter run, name→path mapping).
- **`--generation-config vllm`** is not in the contract; without it the server would silently sample with top_k 20 for any client that omits top_k (INF-D3).
- **Prefix caching** is on as the contract says, although T3's validated route had it off; the gate runs on the server as configured, and the greedy requests are sent after the prompt-log-prob requests so that they can hit cached prefixes.
