## T1-D4 — Probes (per context; all four models ps_A, ps_B, ctrl_B, parent on identical contexts)
- **Opener log-probs (unchanged from Part P):** for each of the 6 frozen openers ("Arr,", "Forsooth,", "Ahoy,", "Prithee,", "Avast,", "Hark,", tokenised alone), the summed log-prob of the opener tokens teacher-forced after the header, via `prompt_logprobs=0` on prompt + opener (Part P's `stage_probe` code). Engine: Part P's `LLM(...)` settings (bf16, max_model_len 8192, prefix caching off, max_num_seqs 256, max_num_batched_tokens 16384).
- **Onset-probe denominator (new):** one extra request per context: prompt = context, `max_tokens=1`, `temperature=0`, `logprob_token_ids` = the 10 `top10_used` ids + the 6 opener first-token ids. These are vLLM 0.30's raw log-probs (`logprobs_mode` raw_logprobs, the default). **Built-in check:** this request's first-token log-probs of the 6 openers must match the teacher-forced `prompt_logprobs` value at the opener's first position (mean |Δ| ≤ 0.05 nat; checked in the smoke before the full run). A mismatch stops the run.
- **Routing probe (frozen, D4 of sw003):** `style(ctx) = mean over the 3 pairs of [lp(pirate opener) − lp(Shakespeare opener)]`. Parent-relative = model − parent on the same context. **Orientation for the Spearman:** the rule compares the probe with the generated *rival* share, so the probe is oriented toward the rival: `routing_probe_rival = style_rel` in ps_B (rival = pirate) and `−style_rel` in ps_A (rival = Shakespeare). The un-oriented pirate − Shakespeare values are reported too. ctrl_B and the parent have no assignment; their values are reported under both orientations as the persona-only floor.
- **Onset probe (frozen, D1):** `onset(ctx) = logsumexp_6(summed opener lp) − logsumexp_10(top10_used lp)`, parent-relative (model − parent, same context). Oriented positive (higher = more style onset). The parent's absolute value is reported too.
- Persona summary = the mean over the persona's 100 s100 contexts.

## T1-D5 — Judge and generated readouts
- Judge: Part P's `style_judge_p.py` (copied byte-identical; sha256 recorded in README), `--mode conv` (assistant turns 3–5 scored, turns 1–2 shown as context, no system prompt shown), judges `glm` and `deepseek`, ALT key, `API_LEDGER=<sw004>/spend.jsonl`, `API_CAP_USD=15`. Expected cost about $2.5; my stop line is $5 for T1.
- Habit labels (frozen, sw003 D4): consensus = mean of the two logprob-weighted scores; pirate habit = consensus pirate > 5; Shakespeare habit = consensus shakespeare > 5. A conversation counts as **styled** if either is > 5.
- **Judged completeness** (sw003 D19 lesson): expected items come from the **chat manifest** (`jobs/chat_manifest.json`: 16 × 100 × 2 = 3,200 keys), not from whatever files exist. Every key × both judges must have a non-error row with both weighted style scores present before any result is read. Error rows get a retry pass. If keys are still missing after two retry passes, they are listed and excluded, with their count reported per persona; nothing is zero-filled.
- **Generated onset** (per persona × organism) = styled conversations / judged conversations.
- **Generated routing** (per persona × organism) = among styled conversations, the share whose rival-style consensus is > 5 and helper-style consensus ≤ 5 (Part P's `rival_share_among_style.share`, i.e. `analyze_P.py`'s definition, with rival = the dismissive character's style for that organism in every persona: A rival Shakespeare, B rival pirate). Secondary: the any-rival share (rival > 5 among styled, mixed conversations included). Mixed (both > 5) counts are reported.
- **Undefined routing (frozen now, before any output):** routing is computed only for personas with **≥ 5 styled conversations** (of 100) in that organism. The primary routing Spearman uses those personas, and *n* is reported. If fewer than **10** personas qualify in an organism, the routing rule **cannot be evaluated** there; the verdict is "not validated (untestable: n < 10)", and that counts as not valid for the census gate, because the rule needs validity in both organisms. Two sensitivity readouts, which do not decide the verdict: (i) all personas with ≥ 1 styled conversation; (ii) a smoothed share `(rival_only + 0.5) / (styled + 1)` for all 16.

## T1-D6 — Statistics and the frozen rule
- **Spearman across personas** (scipy `spearmanr`, average ranks for ties): routing probe (rival-oriented, parent-relative) vs generated routing; onset probe (parent-relative) vs generated onset. Per organism (ps_A, ps_B).
- **Bootstrap CI** (2,000 resamples, percentile 95%, `numpy.random.default_rng(0)`): generation scripts and probe scripts are resampled independently. Within a side the same resampled script indices apply to every persona, which keeps the script-level correlation. Each draw recomputes the persona summaries and the Spearman. For the matched secondary (53 overlap scripts), one shared resample is used for both sides. A draw where a persona's routing becomes undefined (< 5 styled) leaves that persona out of that draw.
- **Frozen rule (design_spec T1), applied to the point estimates:** the routing probe is valid if Spearman ≥ 0.7 in **both** ps_A and ps_B; the onset probe likewise against generated onset. The CIs are reported beside the point estimates and do not change the verdict.
- **Reliability:**
  - (a) s100 routing probe: split-half by sorted s100 index (scripts 0–49 vs 50–99; this split is also a topic split: the first half is bbq / tile / dinner / ho_bbq / most of ho_tile, the second the rest). Per-persona means in each half, Pearson r across the 16 personas, Spearman–Brown `2r/(1+r)` (reliability of the 100-script mean). Spearman-rank split-half r → SB is reported as secondary, and so is an odd/even split. Per organism, for the parent-relative rival-oriented probe (primary) and the absolute probe (secondary).
  - (b) Part P's existing s20 persona map (`sw003 src/P_eval/out/probe_ps_{A,B}.jsonl` and `probe_parent.jsonl`, set pmap, all 25 focused personas): sorted s20 scripts 0–9 vs 10–19, parent-relative per-persona means, Pearson across 25 personas → SB = reliability of the s20 map. Also reported on the 16-persona subset.
  - (c) Supplementary: the s20-equivalent reliability from my s100 data (mean over 200 random 10-vs-10 script splits, SB to 20).
  - **s20/s40 rule (frozen):** the census uses s20 if the s20 split-half SB reliability ≥ 0.8, else s40. The deciding number is (b) on all 25 personas, per organism; s20 requires ≥ 0.8 in **both** organisms. (b) on 16 personas and (c) are reported beside it.
- **If a probe fails:** for each persona that breaks it (largest absolute rank residual between probe rank and generated rank; the top 3 per failing organism, plus any persona whose routing is undefined), I read 10 conversations (seeded random sample from that persona × organism, `random.Random("sw004-T1-read|<org>|<persona>")`) and quote them. Then I stop. No census is started.
